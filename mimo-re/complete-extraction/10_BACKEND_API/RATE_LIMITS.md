# ۱۰ه — محدودیت نرخ، صفحه‌بندی، نسخه‌بندی

## ۱. شواهد

| موضوع | وضعیت |
|---|---|
| هدر `RateLimit-*` یا `Retry-After` | ❌ یافت نشد |
| صفحه‌بندی (`page`, `cursor`, `offset`) | ❌ در مسیرها یافت نشد (همه شناسه‌محور) |
| صفحه‌بندی فالوور/لیدربورد | احتمالاً در بدنه (UNKNOWN) |
| نسخهٔ API | `v1` + یک `v2` (`/v2/client-config`, `/v2/purchase`) ⇒ نسخه‌بندی مسیر |
| نسخهٔ کلاینت | `version_name 9.35` + `publishSetVersion 753` |
| Client config | `/v2/client-config` (GET) | Remote config اختصاصی |

## ۲. نتیجه‌گیری صادقانه

نمی‌توان ادعا کرد Mimo محدودیت نرخ دارد یا ندارد؛ **UNKNOWN**. تنها شاهد،
وجود سهمیه‌های دامنه‌ای (کلید، مربی، تمرین) است که در لایهٔ محصول اعمال می‌شوند.

## ۳. توصیهٔ الزامی برای محصول هدف

| مورد | طرح |
|---|---|
| نرخ کلی | ۱۰۰ درخواست/دقیقه/کاربر، ۶۰۰/دقیقه/IP |
| ارسال پیشرفت | تجمیع (batching) هر ۳۰s + در پایان درس |
| صفحه‌بندی | cursor-based برای بانک سؤال (حجم بالا) |
| نسخه‌بندی | `/v1` + هدر `X-Min-Client-Version` برای اجبار به‌روزرسانی |
| Idempotency | `Idempotency-Key` روی POST پیشرفت (کلید: lessonId+attempt) |
