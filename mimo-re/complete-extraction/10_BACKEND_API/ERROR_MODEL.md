# ۱۰د — مدل خطا

## ۱. شواهد در بسته

| لایه | شاهد | معنا |
|---|---|---|
| شبکه | ۱۴ رشتهٔ `*_offline_*` | حالت آفلاین به‌جای پیام خطا |
| عمومی | `generic_error_retry`, `error_try_again` | بازتلاش دستی |
| دامنه | ۷۱ رشتهٔ `*error*` (`authentication_error_*`, `purchase_error_*`, `code_error_*`) | تفکیک خطا |
| مربی | `ai_tutor_*error*` | خطای مدل |
| اجرا | `input_console_error*`, `compiler_error*` | خطای کد |

## ۲. الگوی استنباطی پاسخ خطا

```
{ "code": "<domain_code>", "message": "<انگلیسی، کاربرنمی‌بیند>", "details": {...} }
```
سرور Mimo بدنهٔ خطای ساخت‌یافته دارد؟ **UNKNOWN** — هیچ DTO خطایی در بسته نبود.

## ۳. طرح پیشنهادی (قطعی، برای پیاده‌سازی)

| کد | HTTP | معنا | رفتار کلاینت |
|---|---|---|---|
| `AUTH_REQUIRED` | 401 | توکن نامعتبر/منقضی | تازه‌سازی، سپس صفحهٔ ورود |
| `FORBIDDEN` | 403 | نداشتن entitlement | مودال ارتقا |
| `QUOTA_EXCEEDED` | 429 | سهمیه (کلید/مربی) | `keys_zero_subtitle` معادل |
| `VALIDATION` | 422 | دادهٔ نامعتبر (پیشرفت) | نگه‌داشتن در صف |
| `CONFLICT` | 409 | نسخهٔ قدیمی | تصمیم ادغام |
| `RATE_LIMITED` | 429 | نرخ | backoff |
| `UPSTREAM` | 502 | خطای اجرای کد/مدل | پیام مهربان + بازتلاش |
| `OFFLINE` | — | نبود شبکه | صف + بنر |

## ۴. قاعدهٔ UX

Mimo هرگز پیام خطای فنی نشان نمی‌دهد؛ همیشه یا حالت آفلاین یا «دوباره تلاش» است.
این الگو **ارزش کپی دارد**: هیچ‌گاه کد خطا به کاربر نمایش داده نشود.
