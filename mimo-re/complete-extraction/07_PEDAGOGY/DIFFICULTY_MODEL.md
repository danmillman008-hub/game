# ۰۷ج — مدل سختی

## ۱. سختی صریح در داده

| سطح داده | مکانیزم | مقادیر |
|---|---|---|
| آموزش | `type` | course / practiceRequired / practiceOptional / guidedProject(±) / challenges |
| فصل | `type` | practiceLevel1…3، challengeLevel0…2 |
| درس | نسخهٔ دوم | `hardModeContent` + `hardModeSelected` (۶,۰۵۸ درس) |
| بلوک | تعداد جای خالی | ۰ تا ۱۲ (میانه ۱.۴) |

## ۲. آنچه به‌عنوان «سختی» استفاده نمی‌شود

هیچ فیلد عددی سختی (1–5)، هیچ برچسب دشوار/آسان برای درس، و هیچ آستانهٔ زمانی وجود ندارد.
سختی = **جایگاه ساختاری** (نوع آموزش + سطح فصل + وجود `hardModeContent`).

## ۳. توزیع تجربی (پروکسی سختی)

| پروکسی | یافته |
|---|---|
| نسبت جای خالی به کاراکتر کد | میانهٔ عرض بازه ۴ کاراکتر (توکن‌های کوتاه مثل `</p>`) |
| چند جای خالی | بلوک‌های ۳+ جای خالی ۲۸٪ بلوک‌های تعاملی |
| درس کدی | فقط ۲۲٪ محتوا، ولی سختی تجربه بالاتر |
| نسخهٔ سخت | ۴۲.۵٪ درس‌های تعاملی نسخهٔ دوم دارند |

## ۴. طرح سختی برای کنکور (پیشنهاد)

| بُعد | سنجه | چرا |
|---|---|---|
| شناختی | سطح بلوم (یادآوری…تحلیل) | Mimo ندارد |
| محاسباتی | تعداد گام حل | جای خالی متعدد ≈ چند گام |
| زمانی | زمان هدف (ثانیه) | کنکور زمان‌محور است |
| دام | تعداد گزینهٔ انحرافیِ مبتنی بر خطای رایج | Mimo: ۱۴,۸۷۰ گزینهٔ انحرافی موجود است، اما بدون برچسب خطا |

**توصیهٔ عملی:** نگاشت `errorCode → distractor` بسازید؛ Mimo فقط «گزینهٔ نادرست» دارد،
نه «گزینهٔ نادرست با تشخیص خطا». این کمبود باید در محصول هدف جبران شود.
