# ۰۸و — محدودیت‌های تحلیل مربی هوشمند

| محدودیت | اثر | جبران |
|---|---|---|
| متن کامل پرامپت بازتولید نشد (قید مأموریت) | جزئیات سبک پاسخ نامعلوم | ساختار ۹ قاعده و جای‌گاه‌ها مستند شد |
| بدنهٔ HTTP درخواست نامعلوم | نمی‌دانیم چه فیلدهایی ارسال می‌شود | فقط DTOها موجودند |
| مدل/تأمین‌کننده نامعلوم | هزینه و کیفیت نامعلوم | — |
| سهمیهٔ عددی نامعلوم | — | سمت سرور |
| Streaming نامعلوم | رفتار UI | احتمال پاسخ کامل |
| ارزیابی کیفیت پاسخ | نیازمند اجرا | **NOT_TESTED** |
| رفتار چندزبانه (فارسی) | نامعلوم | R7 می‌گوید «هم‌زبان کاربر» |
| منطق «ExplainError» | فقط نام دکمه | محتوای ارسالی نامعلوم |

## آنچه می‌توان با اطمینان بالا گفت

1. مربی **دو حالت** دارد (کدی/تعاملی) با ساختار پرامپت یکسان.
2. پرامپت **در کلاینت ساخته می‌شود** (کلاس‌های `SystemMessage`/`UserMessage` در بسته).
3. «پاسخ درست» (`solvedContent`) **به مدل داده می‌شود** — بزرگ‌ترین تفاوت با یک طراحی امن.
4. پاسخ سرور شکلی همانند `{conversationId, content, finishReason}` دارد.
5. سهمیه بر تعداد پیام کاربر استوار است، نه توکن.
