# ۰۶ب — مشخصات اجراکنندهٔ درس تعاملی

هدف: قرارداد دقیق برای بازتولید بازیکن تعاملی بدون نیاز به کد Mimo.

## ۱. ورودی/خروجی

```
input:  { lessonId, tutorialId, chapterId, publishSetVersion, tutorialVersion, payload }
output: events → progress api
```

## ۲. چرخهٔ حیات

| مرحله | عمل | الزام داده |
|---|---|---|
| 1. resolve | یافتن درس در بستهٔ محلی؛ اگر نسخهٔ بسته ≠ `publishSetVersion` پیشرفت، تصمیم مهاجرت | بخش ۰۴ |
| 2. parse | اجرای `tools/lesson_dsl.py:parse` (یا معادل) | ۰۵ |
| 3. render | ساخت AST → ویو (بخش ۰۵ج) | ۰۵ |
| 4. interact | جمع‌آوری چیپ‌ها/ورودی/انتخاب‌ها | ۰۵ت |
| 5. check | تصحیح محلی (تعاملی) یا ارسال به سرور (کدی) | ۰۵ت / ۰۶ج |
| 6. feedback | نمایش `visible-if` مربوط | ۰۵ث |
| 7. persist | نوشتن رکورد پیشرفت در صف outbox | ۱۱ |
| 8. advance | درس بعد/پایان فصل | ۰۶ |

## ۳. قرارداد دادهٔ پیشرفت (پیشنهاد، هم‌خوان با شواهد)

```json
{
  "lessonId": 67389, "tutorialId": 1001, "chapterId": 42,
  "tutorialVersion": 3, "publishSetVersion": 753,
  "state": "completed", "attempts": 2, "wrongCount": 1,
  "completedAt": "2026-11-01T10:00:00Z", "durationMs": 42000,
  "hardMode": false, "source": "interactive"
}
```
* `attempts`/`wrongCount` برای «تمرین هوشمند» لازم است (بخش ۰۷).
* زمان و شمارش، در Mimo وجود دارد؟ **PARTIALLY_VERIFIED** (رشتهٔ `practice_*` و جدول پیشرفت
  فقط کلیدهای نسخه/وضعیت را نشان می‌دهد؛ شمارش تلاش در بستهٔ محلی قابل اثبات نیست).

## ۴. حالت‌های ویژه

| حالت | رفتار لازم |
|---|---|
| آفلاین | نمایش کش، صف کردن پیشرفت، بنر `*_offline_*` |
| بازگشت به درس نیمه‌تمام | بازسازی پاسخ‌ها **یا** شروع از صفر (Mimo: UNKNOWN) |
| تغییر زبان | بستهٔ محتوا عوض می‌شود ولی پیشرفت حفظ می‌شود (تک‌شناسه) |
| نسخهٔ سخت | `hardModeSelected` تعیین می‌کند کدام نسخه دیده شود |
| deep link | `/learn/…` باید به درس درست برسد |

## ۵. الزامات کارایی

* پارس تنبل: فقط درس جاری.
* حافظهٔ نهان AST: `lessonId+tutorialVersion` کلید.
* رندر باید ۲۱,۱۰۸ بلوک را در ۱۶۰ms (میانه) ممکن کند؛ بلوک کد میانه چند صد کاراکتر است.
