## ۳. دستور زبان رندررها ( آنچه واقعاً در `interactiveContent` دیده شد)

| سیگنال | فراوانی | کارکرد آموزشی |
|---|---:|---|
| `code` / ویرایشگر و وبویو | ۱۳٬۵۸۰ | **یادگیری با انجام**: خروجی بلافاصله دیده میشود |
| `fillTheGap` | ۶٬۵۰۴ | یادآوری فعال با کمترین بار نوشتن |
| `validatedInput` | ۱٬۷۷۲ | پاسخ کوتاه، نرمالسازی و بررسی |

## ۴. الگوی گفتار آموزشی (devices اندازهگیری‌شده روی ۱۸٬۲۷۲ درس)

| الگو | فراوانی | معنا |
|---|---:|---|
| `instruction/try` (`let's / try it / now you / type / run / create …`) | **۵٬۰۴۸** | غالبترین لحن: **دستور به انجام**، نه توضیح منفعل |
| `explain/define` (`is a / means / called / stands for …`) | ۱٬۱۰۹ | تعریف کوتاه، بلافاصله بعد از آن انجام |

| `feedback/recap` (`well done / correct / you learned / summary …`) | ۴۳۳ | بازخورد فوری و جمع بندی |
| `example` (`for example / such as …`) | ۲۵۶ | مثال عینی، کم و بهجا |
| `scaffold/hint` (`hint / tip / note / careful …`) | ۵۳ | راهنما فقط هنگام نیاز |

**نسبت «انجام» به «توضیح» ≈ ۴٫۵ به ۱.** این مهمترین یافتهٔ پداگوژیک است.

## ۵. چرخهٔ یادگیری میمو (بازسازی شده، فقط از شواهد محلی)

```
۱. HOOK/EXPLAIN  ریزدرس ۲۰کلمهای + تعریف + مثال          (noninteractiveSlide)
۲. DO            دستور «حالا تو انجام بده»               (code / webview)
۳. CHECK         پاسخ کوتاه/جای خالی/چندگزینهای          (fillTheGap, MCQ)
۴. FEEDBACK      «درست شد / دوباره امتحان کن» + ادامه    (feedback bottom sheet)
۵. REPEAT        همان مفهوم در سطح بالاتر فصل بعدی       (practiceLevel1→2→3)
۶. CHALLENGE     پروژه/چالش بدون راهنما                  (challengeLevel0→2)
۷. RECOVERY      تلاش ناموفق هم «حلشده» محسوب میشود
```

مورد ۷ **VERIFIED** از M07/M09: `isSolvedCorrectly() ≡ tries >= 1`؛ یعنی سیستم
به «تلاش» پاداش میدهد نه فقط به پاسخ درست. validators هم عینیاند:
- چندگزینهای: `all(selected == isCorrect)`
- جای خالی / املا: برابری ترتیبی لیست
- `executableFiles`: `List.equals`
- `validatedInput`: نرمالساز `Locale.US`

بازخورد در UI میمو (پروتوتایپ نهایی v12.5-fa هم حفظ کرده): پنل feedback،
یک دکمهٔ بنفش تمامعرض «ادامه»، دکمهٔ مربعی «سؤال قبل»، نوار پیشرفت ۶dp و پرچم گزارش.

## ۶. قواعد انتقال درسنامهٔ زیست به سبک میمو (بدون افت عمق)

| اصل میمو | اقدام روی کتاب زیست |
|---|---|
| یک مفهوم / ریزدرس | هر پاراگراف/نکتهٔ درسنامه → یک `lesson` با `pedagogicalRole` مشخص |
| ≈۲۱ کلمه | متن فارسی وفادار، کوتاه، **بدون حذف نکته**؛ نکات بلند به چند ریزدرس تقسیم میشوند (تقسیم ≠ خلاصهسازی) |
| انجام > توضیح (۴٫۵:۱) | بعد از هر ریزدرس، تست مرتبط همان صفحه بهعنوان `block` چک قرار میگیرد |
| تکرار در سطوح | همان مفهوم در `practiceLevel1→2→3` با تستهای ساده→دشوار کتاب تکرار میشود |
| چالش پایانی | تستهای ترکیبی/سطحبالای کتاب → `challengeLevel2` |
| بازخورد فوری | پاسخنامهٔ کتاب (در صورت وجود) → `explanationFa`؛ در غیر اینصورت خالی + `notes` |
| تلاش = پیشرفت | رفتار `tries>=1` در اپ آفلاین حفظ میشود |
| تستها دوبار مصرف میشوند | `questions[]` (بانک) + `chapter.practiceQuestionIds` (تمرین بیزمان) + `exams[].questionIds` (آزمون) |
| ردگیری | هر جمله `trace.sourcePage` دارد؛ هیچ محتوایی اختراع نمیشود |

**مرز صداقت:** ترتیب دقیق درسها، سیاست واقعی قفل و پاداش سروری میمو نامعلوماند
(M09 `SERVER CONFIRMED=0`). قواعد بالا «بازسازی از دارایی لوکال + تصمیم مستقل
برای تبدیل کتاب»اند، نه ادعای رفتار قطعی سرور میمو.
