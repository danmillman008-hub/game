## ۲. تصمیم طراحی: شبکهٔ ۳ ستونه RTL از «گره»

چرا ۳تایی: (الف) خواستهٔ صریح شما؛ (ب) با `content_max_width 608dp` و گاتر `16dp`، عرض هر گره `(608 − 2×16)/3 ≈ 192dp` میشود که تقریباً همان مقیاس گره فصل میمو است؛ (ج) در `sw600dp` با ۴ ستون و گاتر `24dp` هم همچنان خوانا است. ترتیب **راست به چپ**: اولین گره ردیف در سمت راست.

```
┌────────────────────────────── AppBar / toolbar (include @layout/toolbar) ───────────────┐
│  آزمونها                                                              [؟]                     │  ← بدون تایمر؛ تایمر فقط داخل آزمون (v2)
├──────────────────────────────── chips فیلتر (همه / جامع / تکدرسی / مبحثی / این ماه) ─────┤
│   ┌────────┐   ┌────────┐   ┌────────┐                                                   │
│   │  ◇     │   │  ◇     │   │  ◇     │   ← گره: card_enabled + card_outline + 12dp radius│
│   └────────┘   └────────┘   └────────┘                                                   │
│   آزمون جامع    آزمون تکدرسی   آزمون مبحثی   ← برچسب 14sp / text_primary / زیر گره      │
│   ┌────────┐   ┌────────┐   ┌────────┐                                                   │
│   │  ✓     │   │  🔒    │   │  ◇     │   ← success / disabled / active (بدون badge تایمر)  │
│   └────────┘   └────────┘   └────────┘                                                   │
│   آزمون این ماه  آزمون نهایی  آزمون زماندار                                               │
└──────────────────────────────────────────────────────────────────────────────────────────┘
                                   [ Learn ] [ Practice ] [ Leaderboard ] [ Profile ]
```

مشخصات گره (همه از توکنهای موجود):

| ویژگی | مقدار |
|---|---|
| پسزمینهٔ عادی / فشرده / قفل / فعال | `card_enabled` / `card_pressed` / `card_disabled` / `card_outline` |
| شعاع / ارتفاع / گاتر | `12dp` / `96dp` (همسان گره فصل) / `16dp` (`sw600dp: 24dp`) |
| پیشرفت | `progress_chapter_primary` + `progress_chapter_background`، ارتفاع `lesson_progressbar_height 6dp` |
| وضعیت موفق/ناموفق | `accent_success` / `error_default` |
| برچسب | ۱۴sp، `text_primary`، حداکثر ۲ خط، `contentDescription` کامل |
| نشانها | تعداد سؤال، قفل، «جدید»، `XP`؛ همگی با آیکنهای میمو (۰ آیکن تازه، ۰ نشان تایمر) |
| کلیک | ripple میمو + `bottom_sheet_slide_in` برای پنل تنظیمات آزمون |

گروهبندی پیشنهادی (همان الگوی «فصلها»ی میمو): `آزمونهای این ماه` → `آزمونهای جامع` → `تکدرسی` → `مبحثی` → `تشریحی/دوباره`. هر گروه یک سرتیتر ۱۶sp و یک ردیف ۳تایی یا چند ردیف. تعداد گرهها زیاد است ولی صفحه لایهای میماند، نه لیست بیپایان.

## ۴. تایمر — **فقط داخل آزمون** (اصلاحیهٔ بازخورد v2)

> «اون تایمر بالا رو نفهمیدم کاربردش رو… باید روش کلیک کنی و یه عددی مشخص کنی بزنی شروع بشه… ولی همه اینها برای زمانیه که وارد آزمون میشی، نه اینکه بیرون باشه تایمر.»
>
> بنابراین **هاب آزمون هیچ تایمری ندارد**: نه chip، نه badge زمان، نه شمارش معکوس. تایمر فقط در صفحهٔ «اجرای آزمون» وجود دارد.

ماشین حالت (بهصورت پروتوتایپ قابل لمس در `DESIGN/index.html` → نمای «اجرای آزمون / تایمر»):

| حالت | UI | اقدام |
|---|---|---|
| `idle` | chip «تنظیم زمان» در نوار بالای **صفحهٔ آزمون** | کلیک ← باتمشیت |
| `setting` | باتمشیت: عدد دقیقه (۱…۳۰۰) + پیشفرضهای ۱۵/۳۰/۴۵/۶۰/۹۰/۱۲۰ | «شروع آزمون» |
| `running` | `mm:ss` معکوس + «توقف» / «تنظیم مجدد» | شمارش معکوس |
| `paused` | عدد متوقف + «ادامه» | ادامه با همان باقیمانده |
| `finished` | `۰۰:۰۰` قرمز، بنر «زمان تمام شد»، گزینهها قفل، ثبت خودکار پاسخها | تنظیم مجدد |

منطق نهایی محصول: `elapsedRealtime()` مونوتونیک (نه ساعت دستگاه)، ذخیرهٔ خودکار هر ۵ ثانیه، ادامهٔ خودکار بعد از kill اپ، `error_default` در ۱۰٪ پایانی، اتمام خودکار و محاسبهٔ درصد. پنلهای «زمان هر سؤال»، «زمان اضافه» (با همان اقتصاد Sparks، بدون خرید)، «توقف موقت» و «خروج؟» (متن همدرس: «Are you sure that you want to exit the exam?») همچنان در همان باتمشیتهای میمویند. محدودیت سقف مطالعهٔ هدفپلاس → **هشدار غیرمسدودکننده**، نه قفل.

## ۴٫۱ پاسخنامه — سیاست بر اساس نوع آزمون (v4)

> «جای کلمهٔ پالت سؤالات میتونستی بنویسی پاسخنامه… یه گزینه برای آزمونهای عادی بزار پاسخنامه. برای یه سری آزمونها این نباید باشه مثلاً جامع و جمع بندی، ولی برای تحلیلی باید باشه… بعد از اتمام یه گزینهٔ پاسخنامهٔ تشریحی و تستی باید باشه عین یه آزمون آنالیز بشه.»

| سیاست | انواع | «پاسخنامه» حین آزمون | بعد از اتمام |
|---|---|---|---|
| `during_and_after` | عادی / تکدرسی / مبحثی / درسی / این ماه / شخصیساخته / سریع / دوباره | ✅ پاسخبرگ (بدون کلید صحیح) | ✅ تستی + تشریحی + تحلیل |
| `during_and_after_analysis` | **تحلیلی** | ✅ | ✅ تحلیل کامل + شبیهسازی «اگر غلطها نزده میذاشتی» |
| `after_only_fixed_time` | **جامع** (زمان ثابت ۲۷۰ دقیقه) | ❌ | ✅ تستی + تشریحی + تحلیل |
| `after_only` | جمع بندی / نهایی / دوره | ❌ | ✅ تستی + تشریحی + تحلیل |

منطق: آزمونهای شبیهساز جلسهٔ واقعی نباید میان آزمون پاسخنامه بدهند؛ آزمونهای تمرینی/تحلیلی بدهند. در **همه**ٔ حالتها بعد از اتمام، پنل نتیجه دو دکمه میدهد: **«پاسخنامهٔ تستی»** (کلید گزینهای + `answerKeyVersion`) و **«پاسخنامهٔ تشریحی»** (توضیح گامبهگام، ارجاع به مبحث، «تعویض سوال»/«حذف سوال») + درصد، غلط/نزده، شبیهسازی و نقشهٔ ضعف. منبع ایده: همدرس («پاسخ تشریحی»، «تعداد غلط»، `AnalyisByLessonsScreenWidget`) و EPM (`WrongView`, کلید پاسخ، تحلیل). ماشینخوان: `CATALOGS/EXAM_TYPES.csv` ستون `answer_sheet_policy`.

## ۴٫۲ هاب قابلاسکرول با لیبل و فیلد قالب (v4)

> «بخش آزمون باید قابلاسکرول باشه چون انواع آزمونها رو قراره اضافه کنیم… وقتی اسکرول میکنیم بخشهای مختلف یه لیبل عنوان هم باید داشته باشند… فیلدهای مشخص باشند… راحتتر وارد میکنیم. آزمونهای جامع مثلاً تایم فیکس باید داشته باشند.»

همهچیز در **همان یک صفحه** (`overflow:auto`) دیده میشود؛ ۷ بخش شمارهدار، هرکدام لیبل + خط `قالب: …` + گرههای ۳تایی RTL. اضافهشدن نوع تازه = یک لیبل + یک خط قالب + سه گره، **بدون صفحهٔ تازه**. جدول کامل: `CATALOGS/EXAM_SECTION_TEMPLATES.csv`. نمونهٔ فیلدها: جامع = «زمان ثابت ۲۷۰ دقیقه · ۲۰۰–۴۰۰ سؤال · نمرهٔ منفی ⅓ · بدون پاسخنامه حین آزمون»؛ زماندار = «مدت قابلتنظیم · ۵–۴۰۰ سؤال · تایمر معکوس».

## ۶. جریان سؤال (سازوکار میمو + ارتقا)

1. بارگذاری Blueprint و بانک سؤال (ESQ 1.0 / JSON میمو) بهصورت آفلاین.
2. نمایش سؤال: `lesson_interactive_singlechoice_fragment.xml` (۴ گزینه)، فرمولها با `<equation>`، شکلها با `<figure>`، `rtlMarker` و نرمالساز فارسی.
3. پاسخ → **بازخورد فوری** میمو (`lesson_interactive_feedback_bottom_sheet_dialog.xml`)؛ در حالت آزمون، بازخورد تا پایان آزمون **به تعویق** میافتد و فقط «ثبت شد» نشان داده میشود (تنها تفاوت رفتاری مجاز، چون ماهیت آزمون است).
4. ذخیرهٔ پاسخ در Room + outbox؛ `answerKeyVersion` و `questionVersion` همراه هر تلاش.
5. اتمام → محاسبه: درصد خام، نمرهٔ منفی ⅓، `تعداد سوالات نزده`, `تعداد سوالات تشریحی`, `تعداد غلط`؛ شبیهساز «اگه غلطها رو نزده میذاشتی، درصدت… » (هدفپلاس)؛ تحلیل بر حسب مبحث (`AnalyisByLessonsScreenWidget` همدرس)؛ نقشهٔ ضعف؛ `تراز`/`رتبه` با `daysRemainingToKunkor`.
6. **مرور/حذف غلطها**: `تمرین اشتباههای تمام مباحث`، `آزمون دوباره`، `مرور مبحث`/هوشمند (همدرس)، FSRS (EPM)، پاسخ تشریحی، قابلیت «تعویض سوال» و «حذف سوال». غلط فقط وقتی از لیست خارج میشود که دو بار متوالی درست پاسخ داده شود (قابل پیکربندی).
7. XP/امتیاز: سختی ۱…۵ (همدرس: ساده/متوسط/سخت/خیلیسخت/المپیادی) × ضریب درس (دروس تخصصی ×۲)، منهای جریمهٔ غلط؛ به همان `daily_sparks_goal_progress_view.xml` و لیگ واریز میشود.
