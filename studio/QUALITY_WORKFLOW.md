# گردش کار «تولید ارزان، انتخاب گران»

> فرض بنیادی: **تولید ویدیو هزینه‌ای ندارد.** پس گردش کار نباید «کمتر تولید کن» باشد؛
> باید **«بیشتر تولید کن، اما فقط برنده‌ها را نگه دار»** باشد.
> گلوگاه واقعی، تولید نیست — **داوری** است. این سند برای همان نوشته شده.

ابزارها: `studio/scorer.py` (داور عینی) · `studio/chainkit.py` (پل فریم) · `studio/filmkit.py` (مونتاژ)

---

## ۱) وارونگی اقتصاد

| باور قدیمی | واقعیت | نتیجه در گردش کار |
|---|---|---|
| هر شات باید بار اول درست دربیاید | یک شات از ۶ تا، با نرخ موفقیت ۳۰٪ ⇒ ۲ خروجی سالم | N تا بزن، فقط برنده‌ها وارد تدوین شوند |
| تولید گران است، پس کم بساز | تولید رایگان، داوری گران | هزینه را از تولید به **دروازه‌های عددی** منتقل کن |
| کیفیت = مدل بهتر | کیفیت = **ورودی بهتر × انتخاب بهتر** | ۷۰٪ بودجهٔ توجه روی lock کاراکتر و انتخاب |

عدد N را از **ابهام** تعیین کن، نه از بودجه:

| نوع شات | N پیشنهادی | چرا |
|---|---|---|
| واید/استقرار | ۲ تا ۳ | ابهام کم |
| مدیوم با دو نفر | ۴ تا ۵ | ریسک جابه‌جایی چپ/راست |
| کلوزآپ چهره | ۶ تا ۸ | رانش هویت، همان چیزی که فیلم قبلی را خراب کرد |
| کلوزآپ با دیالوگ | ۴ تا ۶ + پاس لب‌سینک | دو ایراد جدا: چهره و دهان |

## ۲) هفت مرحله

### ۰. صدا اول (بدون استثنا)
هر خط دیالوگ جدا TTS می‌شود. **طول هر خط، طول شات را تعیین می‌کند**، نه ۴ ثانیهٔ پیش‌فرض.
`filmkit sync` می‌گوید کدام خط از روی برش رد می‌شود.

### ۱. قفل کاراکتر (گران‌ترین سرمایه‌گذاری، یک بار)
۸ تا ۱۲ پرتره از هر کاراکتر ⇒ داور انتخاب می‌کند ⇒ **یک چهرهٔ قانونی**
+ سه نما (روبرو، سه‌چهارم، نیم‌رخ) به‌عنوان `CHAR_LOCK`.

این تنها چیزی است که رانش لباس/شال‌گردن را می‌بندد. در فیلم قبلی نداشتیم و
دقیقاً همان اتفاق افتاد.

### ۲. طراحی شات (روی کاغذ، نه روی مدل)
هر شات: اندازه، زاویه، لنز، حرکت دوربین، جهت صفحه، گوینده، مدت، و
«کاراکترهای حاضر». یک شات بدون گویندهٔ مشخص = یک شات بی‌مصرف.

### ۳. استیل‌ها با N تا کاندید
هر شات ۶ تا ۸ استیل با ارجاع به `CHAR_LOCK` ⇒ داور عددی (SSIM هویت، شارپنس،
ترکیب‌بندی) برنده را انتخاب می‌کند ⇒ **استیل برنده** ورودی مرحلهٔ بعد است.

### ۴. حرکت با N تا کاندید
از استیل برنده، ۳ تا ۴ کلیپ. `scorer.py` چهار دروازه را می‌سنجد:
رانش هویت، فریز، فلیکر (ذوب شدن)، شارپنس، و پروکسی لب‌سینک.

### ۵. پل فریم اول/آخر (FLF)
برای شاتی که «باید به شات بعد وصل شود»، ورودی = استیل برندهٔ A (فریم اول)
و استیل برندهٔ B (فریم آخر). این تنها راهی است که برش دقیقاً سر جایش می‌نشیند.

### ۶. پاس لب‌سینک، فقط روی ۵ تا ۶ کلوزآپ دیالوگ
صدا ایزوله (بدون موسیقی) → مدل audio-driven → خروجی. روی واید و پشت‌به‌دوربین
لازم نیست؛ همان‌جا هزینه کردن اسراف است.

### ۷. تدوین audio-first + کنترل
`concat -c copy` (ثانیه‌ها) → زیرنویس libass → `loud` → `qc` → `scorer` روی فیلم نهایی.
اگر هر دروازه‌ای رد شد، **فیلم تحویل نمی‌شود**.

## ۳) داور عینی — `studio/scorer.py`

بدون GPU، بدون ابر، روی CPU:

| متریک | چه چیزی را می‌گیرد | آستانهٔ پیش‌فرض |
|---|---|---|
| `identity_ssim` | فریم اول در برابر استیل مرجع | ≥ ۰.۵۵ |
| `identity_ssim_last` | رانش در پایان همان ۴ ثانیه | گزارش، برای تصمیم FLF |
| `face_ssim` | ناحیهٔ چهره (Haar) در برابر مرجع | گزارش |
| `sharpness` | واریانس لاپلاسین — نرمی/نویز | ≥ ۴۰ |
| `frozen_ratio` | نسبت فریم‌های بی‌حرکت | ≤ ۰.۲۵ |
| `flicker` | ناپایداری فریم‌به‌فریم | گزارش |
| `color_shift` | انحراف Lab از مرجع | گزارش |
| `lipsync_r` | همبستگی حرکت ناحیهٔ دهان با پوش صدا (±۶ فریم جست‌وجوی تأخیر) | ≥ ۰.۱۵ |

`lipsync_r` یک **پروکسی** است، نه تشخیص‌گر آموزش‌دیده: اگر دهان حرکت نکند یا با
شدت صدا همبسته نباشد، عدد پایین می‌آید. برای مرتب‌کردن کاندیدها کافی است، برای
«تأیید نهایی» نه.

مثال واقعی روی همان کلیپ‌های فیلم قبلی:

```
python3 studio/scorer.py score clips/s28_t1.mp4 --ref stills/s28_arad_c5.png --audio vo/s28_arad.mp3
→ identity_ssim 0.989 | identity_ssim_last 0.342 | face_ssim 0.843
  lipsync_r 0.124  → رد شد: «دهان با صدا همراه نیست»
```

یعنی: کلیپ در فریم اول دقیقاً همان استیل است، اما تا ثانیهٔ چهارم **۶۶٪ از هویت
فاصله گرفته**. این عدد، دلیل فنی «چرا فیلم قبلی شات‌ها به هم نمی‌خورد» است.

## ۴) چه چیزی از ریپوها برداشت شد (با مسیر فایل)

### `BitraAI/ai-film-director` — اسکیمای داده
`.opencode/agents/*.md` و `schemas/*.yaml` (۱۵ فایل). قابل برداشت:
- قاعدهٔ «هر شات باید به پرامپت تصویر و پرامپت ویدیو و رویداد صوتی نگاشت شود»
- چک‌لیست `continuity-agent.md`: لباس، مدل مو، سن، اشیاء، مکان، زمان، آب‌وهوا،
  نور، **جهت صفحه**، تداوم دوربین، ترتیب زمانی
- `shot.schema.yaml`: `shot_size / angle / lens / camera_height / camera_movement /
  framing / composition / subject / action / duration`
⚠️ خودِ ایجنت‌ها فقط ۲۳ تا ۵۷ خط پرامپت‌اند؛ ارزش در اسکیماهاست، نه در کد.

### `HITsz-TMG/VideoClaw` — مکانیک تولید و انتخاب
`video-claw/backend/core/agents/video_agent.py` (۶۹۲ خط):
- **چهار حالت تولید**: `first_frame` / `start_end_frame` / `reference` (چند عکس مرجع) / `shot_type=multi`
- **مدیریت نسخه**: `_next_version_path()` ⇒ `segment_v2.mp4`, `_v3` — هرگز بازنویسی نمی‌شود
- **فرمت پرامپت سه‌بخشی**: `风格控制` + `人物列表` + `分镜列表：分镜1：[N秒] ...` + «زیرنویس و واترمارک نساز»
- **داور VLM** در `character_agent.py:306`: امتیاز ۱ تا ۱۰، قبولی ≥ ۷ و نبود خطای سخت
- **`doctor_agent.py`**: خطا را دسته‌بندی می‌کند، پرامپت را بازنویسی می‌کند، حداکثر ۳ تلاش
- **انتخاب ذخیره می‌شود** (`selected`) و در مرحلهٔ بعد به‌عنوان مرجع برمی‌گردد ⇒ همان «قفل»

### `HKUDS/ViMax` — منطق دقیق داور
`agents/best_image_selector.py` (۱۹۰ خط). معیارهای صریح داور:
۱) **تداوم کاراکتر**: جنسیت، قومیت، سن، چهره، اندام، لباس، مدل مو
۲) **تداوم فضایی**: چپ/راست کاراکترها، چیدمان، پرسپکتیو
۳) **دقت توصیف**: آیا تصویر همان چیزی است که متن می‌گوید
+ «سلیقه‌ای قضاوت نکن»، «تصویر با حاشیهٔ سفید/سیاه را رد کن»، خروجی = ایندکس + دلیل.
این دقیقاً همان پرامپتی است که یک منتقد بینایی باید بگیرد.

### `showlab/MovieAgent` — ساختار داده
`dataset/<Film>/character_list/<Name>/` + `script_synopsis.json`: هویت‌ها **قبل از**
شات‌ها تعریف می‌شوند، و هر شات به همان شناسه‌ها ارجاع می‌دهد.

### `MeiGen-AI/InfiniteTalk` — دوبلهٔ ویدیوی موجود
عنوان دقیق: *Sparse-Frame Video Dubbing*. ورودی = ویدیو + صدا ⇒ ویدیوی جدید با
همگام‌سازی لب **و سر، بدن و حالت چهره**. `--mode streaming` برای طول نامحدود،
`--size infinitetalk-480|720`، و `--num_persistent_param_in_dit 0` برای VRAM کم.

### `artokun/comfyui-mcp` — بیشترین دانش فنی عملی
`plugin/skills/wan-flf-video/SKILL.md` و `wan-multitalk/SKILL.md`:
- **Wan 2.2 I2V معماری split-noise است**: یک مدل HighNoise و یک LowNoise.
  **باید دو پاس `KSamplerAdvanced`** اجرا شود. یک مدل تنها = خروجی شکسته.
  lightning: ۴+۴ استپ، `shift=5`، `uni_pc`/`beta`، cfg=1.
  غیر lightning: ۲۰ استپ، شکست در ۱۰، cfg=4، `euler`/`simple`، `shift=8`.
- `WanFirstLastFrameToVideo` با `clip_vision_start/end`، `length=81` (گام ۴)
- تصاویر باید **قبل** از FLF و CLIPVision به رزولوشن هدف ریسایز شوند
- نگتیو اجباری (فهرست کیفیت: overexposed, static, worst quality, deformed…)
- **MultiTalk**: باید `AudioSeparation` + `AudioCrop` قبل از Wav2Vec اجرا شود
  (صدای جدا نشده ⇒ دهان دنبال سیگنال اشتباه می‌رود). تک‌گوینده.
  **۴۸۰p ده‌ثانیه ≈ ۸ تا ۱۲ گیگ VRAM؛ ۷۲۰p ≈ ۱۱ تا ۱۶ گیگ.**
  با lightx2v فقط ۴ تا ۸ استپ.

یعنی «برای لب‌سینک باید GPU چند‌هزار دلاری داشته باشی» **غلط** است: یک کارت ۱۲ گیگی کافی است.

## ۵) از کجا معلوم این گردش کار بهترین است؟

سه سطح جواب:

**الف) در محدودهٔ Mivi (بدون GPU):** بله، بهینه است. چون Mivi نه seed می‌دهد، نه
تصویر مرجع، نه فریم آخر، تنها اهرم باقی‌مانده **تعداد برداشت و کیفیت انتخاب** است.
هر کاری جز این، زمان تلف کردن است.

**ب) در مطلق:** نه. بهترین حالت ممکن این است:

```
CHAR_LOCK (چند نما) ──► استیل هر شات (N تا) ──► FLF: استیل A → استیل B
                                                     │
                                دیالوگ ──► InfiniteTalk/MultiTalk (فقط کلوزآپ)
                                                     │
                                    تدوین audio-first ──► دروازه‌های scorer
```

تفاوت با Mivi: در این حالت **واریانس را کنترل می‌کنی** (مرجع، seed، فریم آخر) نه
اینکه با N تا زدن دنبال شانس بگردی. برداشت بیشتر واریانس را زیاد می‌کند؛
FLF و CHAR_LOCK واریانس را **کم** می‌کنند. آن که کیفیت می‌سازد دومی است.

**ج) مهم‌ترین نکته:** بزرگ‌ترین اهرم کیفیت، تعداد برداشت نیست — **کیفیت ورودی** است.
در فیلم قبلی، ۳۷ شات از ۷ استیل با کراپ ساخته شد. صدهزار برداشت هم از یک کراپ
بد، شات خوب نمی‌سازد.

## ۶) SOP

```bash
# ۱ صدا
python3 studio/filmkit.py vo   <film>
python3 studio/filmkit.py sync <film>          # خطی که از برش رد می‌شود را می‌گوید

# ۲ قفل کاراکتر (یک بار برای هر کاراکتر)
#    → CHAR_LOCK = چهرهٔ منتخب + سه نما

# ۳ هر شات: N استیل → داور
python3 studio/scorer.py pick cands/*.png --ref CHAR_LOCK.png

# ۴ هر شات: N کلیپ → داور
python3 studio/scorer.py pick cands/*.mp4 --ref still_winner.png --audio vo.mp3

# ۵ پل فریم برای شات‌های مجاور
python3 studio/chainkit.py bridge <film> --still still_winner.png --prompt "..."

# ۶ مونتاژ (audio-first) — سریع
python3 studio/filmkit.py assemble <film> --crossfade 0 --copy

# ۷ تحویل فقط با عبور از همهٔ دروازه‌ها
python3 studio/filmkit.py qc <film> && python3 studio/filmkit.py loud <film>
```
