# حجم ریپو — عدد واقعی و راه‌حل‌ها

> برای اینکه یک روز ریپو باز نشود و ۱.۲۵ گیگابایت باشد بی‌خبر. اندازه‌گیری
> ۲۰۲۶-۱۰-۳۰، در همین کلون.

## عددها

| سنجه | مقدار |
|---|---|
| حجم `.git` | **۱.۲۵ GB** |
| فایل‌های tracked در HEAD | ۶۹۰ فایل، ۶۹۳ MB |
| بزرگ‌ترین فایل tracked | `deliver/scene_min1.mp4` — ۲۳ MB |
| بزرگ‌ترین blob در تاریخ | **۹۵ MB** |

## منبع مشکل — یک فایل، پنج نسخه

| حجم | مسیر در تاریخ |
|---|---|
| 95 MB | `films/before_leaving/out/final.mp4` |
| 91 MB | همان فایل، نسخهٔ بعد |
| 90 MB | همان، نسخهٔ بعد |
| 68 MB | `films/before_leaving/out/subcheck.mp4` |
| 52 + 52 MB | دو نسخهٔ دیگر از `final.mp4` |
| 22 MB | `deliver/scene_min1.mp4` |

جمع ~۴۷۰ MB فقط از **پنج نسخه از یک فایل**. `.gitignore` امروز
`films/*/out/*.mp4` را نادیده می‌گیرد — ولی آن قاعده **بعد** از کامیت‌شدن این
نسخه‌ها اضافه شد. گیت هر نسخه‌ای که کامیت شود را برای همیشه نگه می‌دارد؛ حذف فایل
در HEAD حجم را برنمی‌گرداند.

## محافظ تازه (پیاده شد)

`studio/links.py` حالا اندازه را هم می‌سنجد:

- **> ۲۰ MB** → هشدار در `make check`
- **> ۴۰ MB** → شکست (کد ۱)، یعنی کامیت در CI رد می‌شود

ینی رندر بزرگ بعدی به‌جای گیت، به درایو می‌رود (`delivery/DELIVERY.md` لینک‌ها را دارد).

## گزینه‌ها برای کم‌کردن ۱.۲۵ GB

| گزینه | نتیجه | هزینه | توصیه |
|---|---|---|---|
| **هیچ کاری نکنیم** | ۱.۲۵ GB می‌ماند | ۰ | فقط اگر فضا مهم نیست |
| **کامیت خالی روی فایل‌های بزرگ** | حجم کم نمی‌شود، فقط HEAD سبک می‌شود | کم | ❌ گمراه‌کننده |
| **بازنویسی تاریخ روی یک میرور تازه** | ~۷۵۰ MB برمی‌گردد | بالا | ⏸ **نیاز به تأیید** |
| **Git LFS برای رسانه** | فایل‌های تازه سبک می‌شوند | متوسط | برای آینده |

### دستور بازنویسی (اجرا نشده — نیاز به اجازهٔ صریح دارد)

بازنویسی تاریخ یک برنچ مشترک، هش‌های همهٔ کامیت‌ها را عوض می‌کند. اجرا **نشد**،
چون تصمیمش با صاحب ریپو است:

```bash
git clone --mirror <repo> repo-mirror.git
cd repo-mirror.git
git filter-repo --strip-blobs-bigger-than 20M    # یا: --path films/before_leaving/out --invert-paths
git push --force
```

بعد از آن همهٔ کلون‌ها باید دوباره clone شوند. تا آن روز، `before_leaving/out/`
در HEAD نیست و فقط در تاریخ زنده است.

## قاعده‌ای که از این‌جا درآمد

1. **هر چیزی که رندر می‌شود، در گیت نمی‌ماند.** کلیپ‌های شات (چند مگ) بله؛ فیلم
   مونتاژشده (ده‌ها مگ) نه — آن به درایو می‌رود.
2. **قبل از هر بچ بزرگ، `make check`** — همان‌جا سقف ۴۰ MB اعمال می‌شود.
3. **هر فایلی که day one باید ignore شود، همان روز ignore شود.** قاعدهٔ اضافه‌شده بعد
   از کامیت، فقط جلوی فایل بعدی را می‌گیرد، نه قبلی‌ها را.
