# آزمون فریم-اول/فریم-آخر (FLF) — نتیجه: **منفی**

> سؤال: اگر `imageUrls` دو عکس بگیرد، آیا عکس دوم **فریم آخر** می‌شود؟ اگر بله،
> هویت کاراکتر تقریباً حل است. جواب: **نه.**

## طرح آزمون

یک جفت، دو اجرا، یک پرامپت، یک عکس شروع:

| جاب | عکس‌ها | پرامپت |
|---|---|---|
| `flf_one` (کنترل) | ۱ عکس: نمای باز بانوی زره‌پوش | «The camera pushes in slowly toward the woman in the white armour. She holds still and rain falls past the lantern.» |
| `flf_two` (آزمون) | همان عکس **+** یک کلوزآپ از همان زن | **همان پرامپت، بدون تغییر** |

اگر API فریم آخر را می‌فهمید، `flf_two` باید به‌سمت کلوزآپ می‌رفت و `flf_one` نه.

## نتیجهٔ عددی

| سنجه | flf_one | flf_two |
|---|---|---|
| فریم اول ≈ عکس اول | ۸.۴ | ۷.۸ (هر دو درست شروع می‌کنند) |
| فریم آخر ≈ عکس دوم (کلوزآپ) | **۷۰.۳** | **۷۱.۹** ← هیچ‌کدام نزدیک نشدند |
| حرکت داخل کلیپ | ۲۱.۳ | ۲۰.۶ |

اختلاف دو کلیپ در طول زمان: ۶.۰ → ۹.۱ → ۱۲.۶ → ۱۳.۷ → ۱۷.۵ (ثانیه‌های ۰.۳، ۱، ۲، ۳، ۳.۸).
این یک واگرایی طبیعی دو نمونهٔ تصادفی است، نه یک همگرایی به فریم دوم. اگر FLF بود،
این عدد باید **به سمت صفر** می‌رفت.

تصویر: `films/anime_ten/qc/flf_probe.jpg` — فریم آخر هر دو کلیپ، هر دو نمای باز است؛
کلوزآپ دوم هرگز ظاهر نمی‌شود.

## حکم

- **`imageUrls[1]` نادیده گرفته می‌شود** (یا حداکثر به‌عنوان تصویر مرجع ضعیف اثر دارد).
- API خطای ۴۰۰ هم نداد — یعنی آرایه را می‌پذیرد و بی‌صدا دور می‌ریزد. این بدترین
  حالت است: شکست خاموش.
- فیلد `end_still` در `mivi_shot.py` و آرایهٔ `images` در `t_video` **باقی می‌مانند**
  (بی‌ضررند و اگر روزی API عوض شد کار می‌کنند)، ولی هیچ برنامه‌ای روی آن‌ها بسته نشود.
