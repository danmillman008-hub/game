# From a screenplay to a finished film — the Mivi stack

Everything here was verified on 2026-10-29 against live Mivi endpoints. No mock paths.

## Proven, end to end

`.probe/probe.py` takes a 8-line screenplay, turns it into 3 shots, and produces a film:

```
[screenplay] 8 lines -> 3 shots
[shot 1] task 60014-1793295510-…  -> shot1.mp4   chained on shot1_last.jpg
[shot 2] task 60014-1793295657-…  -> shot2.mp4   chained on shot2_last.jpg
[shot 3] task 60014-1793295797-…  -> shot3.mp4   chained on shot3_last.jpg
[assemble] xfade            -> film.mp4         11.29 s
[subtitles] burned          -> film_subbed.mp4
[probe] 960×1280  32 fps  11.3125 s  7,465,207 B
```

Every shot was generated by an OpenAI-agnostic MCP tool call, chained through the last
frame of the previous shot. Files: `probe_out/shot{1,2,3}.mp4`, `probe_out/film.mp4`,
`probe_out/film_subbed.mp4`.

What held: identity, room, lighting, and framing continuity across three hops.
What drifted: the costume brightened slightly by shot 3 — chain two hops at most
before re-anchoring on an approved still.

## The two halves

| Half | What it is | Why this one |
|---|---|---|
| **Generation** | `bridge/mivi_mcp.py` — 8 Mivi tools + 4 ffmpeg tools over MCP | Mivi only, since that is the account we have. Nothing to install, stdlib only. |
| **Direction** | `bridge/FILM_DIRECTOR_SKILL.md` | The 4.03 s / no-seed / no-audio limits are written into the workflow, so an agent does not design shots it cannot shoot. |

### What we deliberately did not adopt

- Anything that requires a non-Mivi model or key (OpenMontage's 20+ video providers,
  Nomi's relays, MiniMax). The scope stays Mivi-only.
- Code-orchestrator frameworks: our limits (4.03 s, no seed, no audio, fixed 960×1280)
  need an agent that can re-plan mid-run, which is the agent-first model, not a DAG.

## Wiring it up

### 1. Mivi MCP server

```json
{
  "mcpServers": {
    "mivi-film": {
      "command": "python3",
      "args": ["/abs/path/bridge/mivi_mcp.py"],
      "env": { "MIVI_USER": "7da75eed37c61d33" }
    }
  }
}
```

12 tools: `mivi_upload`, `mivi_video`, `mivi_video_status`, `mivi_video_wait`,
`mivi_compose`, `mivi_upscale`, `mivi_swapface`, `mivi_masks`, `film_last_frame`,
`film_concat`, `film_subtitle`, `film_probe`.

### 2. Editing (optional, if you want more than ffmpeg one-liners)

```bash
npx ffmpeg-skill          # 42 typed tools, MCP + SKILL.md
```

### 3. A studio shell (optional)

- Jellyfish: set the OpenAI provider `base_url` to `http://127.0.0.1:8099/v1`
  (`bridge/mivi_bridge.py`), model `mivi-gx-720p`. Verified: that exact payload shape
  renders a 960×1280 4.03 s clip.
- OpenMontage: add `tools/video/mivi_video.py` that shells into `mivi_mcp.py`'s handler,
  plus a capability entry. Its pipelines then offer Mivi next to the paid vendors.

## Honest limits

| Limit | Consequence |
|---|---|
| 4.03 s per shot, no duration control | a 60 s film is 15–17 shots |
| no seed, no end frame | a shot cannot be re-rendered identically; chaining is the only continuity tool |
| no native audio | VO/TTS + music must be added in post |
| 960×1280 max | vertical only; 16:9 needs pad/crop |
| costume drifts after ~2 chained hops | re-anchor on an approved still |
| text-to-video not available | every shot starts from a still |
