# قوانین پروژه — بالاتر از هر Skill

> این فایل بر همهٔ منابع `agent-skills/vendor/` **مقدم** است.
> اگر مهارتی چیزی خلاف این‌ها گفت، اینجا برنده است. دلیل: این‌ها تصمیم‌های تأییدشدهٔ
> کارفرما و وضعیت واقعی کدِ ما هستند، نه توصیهٔ عمومی یک ریپوی آموزشی.

## ۱. محصول و دامنه

- **Android-only.** هیچ‌وقت KMP، `expect/actual`، iOS یا ماژول مشترک چندسکویی اضافه نکن.
  (مهارت‌های `08-kmp-cmp.md` و بخش‌های multiplatform فقط «مرجع» هستند.)
- **آفلاین اول.** هیچ قابلیت اصلی نباید به اینترنت وابسته باشد. بدون شبکه، اپ باید کامل کار کند.
- **بدون اکانت آنلاین.** دادهٔ کاربر روی دستگاه می‌ماند.
- **مدل دادهٔ v1 تثبیت شده:** دارو (با IRC اختیاری، غیر UNIQUE، بی‌اثر) → بچ → موجودی.
  تغییر schema فقط با migration و پس از بررسی اثر روی APK.
- **ممنوعیت OCR.** ورود داده با تایپ یا اسکن بارکد.
- **آستانه‌ها:** کمبود = مجموع بچ‌های یک دارو ≤ مقدار تنظیمات (پیش‌فرض ۱۰)؛
  نزدیک انقضا = پیش‌فرض ۹۰ روز. **هیچ‌کدام روی `Drug` ذخیره نمی‌شوند.**
- **فارسی + RTL + فونت وزیرمتن** بخشی از هویت محصول است، نه تزئین.

## ۲. معماری فعلی — تغییر بدون ADR ممنوع

```
UI (Compose) → ViewModel (UiState) → UseCase → Repository (interface) → Room / DataStore
```

- **DI ما Koin است، نه Hilt.** فایل‌های `android-di-hilt`، `05-hilt-di.md` و امثال آن‌ها
  فقط برای درک الگو هستند؛ **هیچ‌جا `@HiltAndroidApp`، `@Inject` یا ماژول Hilt اضافه نکن.**
- **معماری «Strict MVI» اجباری نیست.** ما UiState + رویداد یک‌طرفه داریم؛ بازنویسی لایه‌ها
  صرفاً برای رعایت MVI سخت‌گیرانه ممنوع است.
- **هر پارامتر سازنده باید در گراف Koin باشد.** مقدار پیش‌فرض سازنده تزریق نمی‌شود
  (این باگ یک‌بار اپ را در شروع کرش کرد — `docs/POSTMORTEM-2026-10-25-launch-crash.md`).
  هر وابستگی جدید ⇒ ثبت صریح + تست `KoinGraphTest`.
- **اتمی بودن موجودی:** تغییر quantity و ثبت رویداد در یک transaction با rollback کامل.
- **Room منبع حقیقت آفلاین است.**

## ۳. Compose — خط قرمزها

- `collectAsStateWithLifecycle` جای `collectAsState` در ViewModel-based state.
- **هیچ IO، query دیتابیس، یا side effect در Composable.** نه `LaunchedEffect` برای خواندن
  دیتابیس، نه ساخت Repository در Composable.
- state پایدار و immutable؛ `data class` با `List` تغییرناپذیر.
- `GlobalScope` ممنوع؛ scope از ViewModel/lifecycle.
- `remember`/`rememberSaveable` درست؛ state بعد از چرخش صفحه و بازگشت از اسکنر حفظ شود.
- لمس‌پذیری ≥ ۴۸dp، `contentDescription` برای آیکون معنادار، کارکرد با فونت بزرگ سیستم،
  کنتراست کافی. عدد و رنگ hard-code نشود؛ از تم استفاده شود.
- RTL واقعی: `start/end` جای `left/right`.

## ۴. اسکنر

- **ML Kit «bundled»** (`com.google.mlkit:barcode-scanning`) — جایگزینی با Code Scanner
  یا نسخهٔ وابسته به Play Services **ممنوع**؛ گوشی بدون GMS باید اسکن کند.
- گیت CI: نبودِ `libbarhopper_v3.so` داخل APK ⇒ بیلد قرمز است. آن را حذف/شل نکن.

## ۵. بیلد و وابستگی

- هیچ فایل از `agent-skills/` نباید داخل `android/` ارجاع داده شود یا وارد APK شود.
  (workflow `skills-check` این را بررسی می‌کند.)
- وابستگی Gradle جدید فقط با دلیل، بررسی اثر روی حجم APK، و تأیید کارفرما.
- `splits { abi }` و minify release را دست نزن؛ اندازهٔ APK گیت است.

## ۶. تست (بدون تست، تحویل نیست)

- منطق دارو/بچ/موجودی ⇒ تست واحد.  
- مسیرهای حیاتی UI ⇒ تست instrumentation / `app-smoke`.
- هر تغییر DI ⇒ `KoinGraphTest` سبز.
- مهارت‌ها **جای تست را نمی‌گیرند**؛ فقط کیفیت کد را بالا می‌برند.

## ۷. نحوهٔ استفاده از مهارت‌ها

1. فقط مهارت مرتبط با کار جاری را بخوان (نه کل مجموعه؛ context را شلوغ می‌کند).
2. خروجی بازبینی را با شدت‌بندی گزارش کن: **Critical / High / Medium / Low**.
3. مهارت «قاضی و چک‌لیست» است، نه دستور تغییر معماری.
4. اگر پیشنهاد یک مهارت با این فایل تناقض داشت، آن را در گزارش به‌عنوان «رد شده»
   با دلیل ثبت کن و طبق این فایل عمل کن.
