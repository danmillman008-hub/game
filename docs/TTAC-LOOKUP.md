# استعلام از سامانهٔ تیتک — دقیقاً چطور کار می‌کند

این سند پاسخ این پرسش است: «اپ دقیقاً کجا و چطور استعلام می‌گیرد؟»
همهٔ مقادیر از کد خود اپ (`TtacParser.kt`, `TtacApi.kt`) و همان چیزی که در
`pharmacy-inventory (3).html` و مهندسی معکوس `ttac-4.3.6.apk` بود گرفته شده است.

## ۱. از کجا شروع می‌شود؟ (سه نقطهٔ ورود)

| نقطهٔ ورود | چه کاری می‌کند |
|---|---|
| **داشبورد → دکمهٔ «صفحهٔ استعلام تیتک»** | صفحهٔ کامل استعلام: ورودی کد + دکمهٔ بزرگ |
| **ثبت سریع**: سوئیچ «استعلام خودکار» روشن باشد | وقتی کدِ ≥۸ رقمی در انبار پیدا نشود، خودکار همان کد پرسیده می‌شود؛ نتیجه با دکمهٔ «ثبت این دارو» به دارو تبدیل می‌شود |
| **افزودن دستی دارو**: کارت «استعلام از سامانهٔ تیتک» | کد GTIN یا IRC را از فیلدها می‌گیرد و با «پر کردن فیلدها» نام/شرکت/GTIN/IRC را پر می‌کند |

هیچ‌کدام خودکار نیست مگر سوئیچ «استعلام خودکار» در صفحهٔ ثبت روشن باشد (پیش‌فرض
روشن — همان رفتار HTML). با خاموش‌کردن آن، اپ ۱۰۰٪ آفلاین می‌ماند.

## ۲. کدام اندپوینت؟ (بر اساس طول کد)

پایه: `https://irfdamobile.ttac.ir/api/` (سرویس خودِ اپلیکیشن موبایل تیتک)

| طول کد | اندپوینت | پارامتر |
|---|---|---|
| ≥ ۲۱ رقم (GS1 با بچ/انقضا) | `WrapperV2/CheckBarcode` | `barcode=` |
| ۲۰ رقم (شناسهٔ رهگیری UID) | `WrapperV2/CheckUid` | `uidCode=` |
| ۱۶ رقم (کد اصالت) | `WrapperV2/CheckSixteenCode` | `sixteenCode=` |
| ۸ تا ۱۵ رقم (GTIN/EAN) | `WrapperV2/CheckBarcode` | `barcode=` |

کد قبل از ارسال: ارقام فارسی/عربی → لاتین، حذف فاصله/خط‌تیره، GTIN به ۱۴ رقم با
صفر پیشرو.

پارامترهای ثابتی که اپ رسمی می‌فرستد (بدون آن‌ها سرور پاسخ نمی‌دهد):

```
&latitude=0.0&longitude=0.0&device=2
&deviceIdentifier=<شناسهٔ ساختگی پایدار>
&Platform=1&PlatformVersion=30&VersionCode=60031&AppVersion=6.9.1
```

هدر: `Accept: application/json, text/plain, */*` — **هیچ کلید API لازم نیست**
(برخلاف سرویس بیمهٔ `checksinglebarcodeuid` که کلید `X-SSP-Api-Key` می‌خواست و
عمداً پیاده نشده).

نمونهٔ واقعی درخواست برای بارکد ۱۴ رقمی:

```
GET https://irfdamobile.ttac.ir/api/WrapperV2/CheckBarcode?barcode=06260000000001
    &latitude=0.0&longitude=0.0&device=2&deviceIdentifier=a-stock-android
    &Platform=1&PlatformVersion=30&VersionCode=60031&AppVersion=6.9.1
```

## ۳. پاسخ سرور و نگاشت آن

```json
{ "ErrorCode": 0,
  "Result": { "persianname": "…", "englishname": "…", "gtin": "…", "irc": "…",
              "manufacturer": "…", "importer": "…", "price": "12500",
              "statuscode": 0, "statusmessage": "…", "batchcode": "…", "expiration": "…" } }
```

قواعد نگاشت:

- `Result` گاهی **آرایه** است → اولین عضو خوانده می‌شود.
- کلیدها بزرگ/کوچک‌حساس نیستند (`PersianName` = `persianname`).
- نام: `persianname` و اگر نبود `englishname`؛ نیم‌فاصلهٔ فارسی حفظ می‌شود.
- شرکت: `manufacturer` → `importer` → `distributer`.
- قیمت: فقط رقم‌ها، به ریال.
- سرور خطا را با **HTTP 500 + بدنهٔ JSON** می‌فرستد؛ بدنه حتی روی کد خطا پارس می‌شود.
- `ErrorCode 1301` = ساختار بارکد نامعتبر → پیام روشن به کاربر، نه کرش.
- `statuscode == 0` یعنی «حکم اصالت اعلام نشده»، نه «تأییدشده».

## ۴. خطاهایی که کاربر می‌بیند (پیام فارسی، بدون کرش)

| وضعیت | پیام |
|---|---|
| بدون اینترنت / DNS | «اتصال به سامانهٔ تیتک برقرار نشد… بدون اینترنت هم ثبت دستی کار می‌کند» |
| تایم‌اوت (۱۲ ثانیه اتصال/خواندن، ۲۰ ثانیه کل) | «سامانه در زمان مجاز پاسخ نداد؛ کمی بعد دوباره امتحان کنید» |
| کد پیدا نشد | «این کد در سامانهٔ تیتک پیدا نشد» |
| خطای سرور | متن `Message` سرور یا «سامانه خطا داد (کد 1301)» |
| کد کوتاه‌تر از ۸ رقم | «کد معتبر نیست؛ حداقل ۸ رقم لازم است» (بدون تماس با شبکه) |

## ۵. حافظهٔ محلی (آفلاین)

- نتیجه در جدول Room `lookup_cache` ذخیره می‌شود؛ **۳۰ روز** معتبر است.
- اگر اینترنت نبود ولی نتیجهٔ قبلی موجود باشد، همان با برچسب
  «از حافظهٔ همین دستگاه» نشان داده می‌شود.
- «پیدا نشد» در حافظه ذخیره **نمی‌شود** (تا بعداً دوباره پرسیده شود).

## ۶. بعد از استعلام

- دکمهٔ «ثبت این دارو و باز کردن آن»: اگر همان GTIN/IRC از قبل در انبار باشد،
  داروی تکراری ساخته نمی‌شود و همان باز می‌شود؛ وگرنه داروی جدید ساخته می‌شود و
  صفحهٔ جزئیات آن باز می‌شود تا بچ/موجودی ثبت شود.

## ۷. حریم خصوصی

فقط همان یک کد (و شناسهٔ ساختگی دستگاه) ارسال می‌شود. هیچ داده‌ای از موجودی،
بیمار، فروش یا نام داروخانه بیرون نمی‌رود. در حالت خاموش‌بودن استعلام خودکار و بدون
زدن دکمه، اپ هیچ درخواستی نمی‌فرستد.
