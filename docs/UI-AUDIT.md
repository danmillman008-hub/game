# بازبینی رابط کاربری فعلی — چه چیزی اضافه است و چه چیزی مشکل دارد

> کارفرما گفت: «در رابط کاربری یک سری بخش‌های اضافی هست و خیلی مشکلات هست.»
> حق دارد. این سند فهرست دقیق آن اضافه‌ها و طرح پیشنهادی جایگزین است.
> **هیچ کدی نوشته نشده**؛ این سند ورودی فاز ۴ (طراحی) است.

---

## ۱) ساختار فعلی (نگاشت شده از فایل موجود)

پنج زبانه + چهار کارت تنظیمات + سه ابزار فنی:

```
زبانه‌ها:  دیتابیس | اسکن و ثبت | موجودی | تاریخچه | هشدار
```

| بخش | چه چیزی داخلش هست | مشکل |
|---|---|---|
| زبانهٔ «دیتابیس» | بارگذاری اکسل، تنظیمات (هشدار انقضا، تقویم)، پشتیبان/بازیابی، حذف همه | ورود کاربر به تنظیمات حساس، همیشه جلوی چشم |
| کارت «بررسی آنلاین» | چک‌باکس فعال، چک‌باکس «مسیر جایگزین»، آدرس پروکسی، کلید API، آدرس سرویس، نام کاربری، رمز، آدرس استعلام | **۹ فیلد فنی** که کارمند داروخانه نه می‌فهمد نه باید ببیند |
| همان کارت | «دریافت/ادامهٔ کاتالوگ»، «کاوش‌گر اندپوینت»، «تست منابع برای UID» | **ابزار توسعه**، نه قابلیت محصول |
| «تست اتصال» + «ذخیرهٔ پاسخ خام» | ابزار عیب‌یابی | جای درستش منوی پشتیبانی است |
| زبانهٔ «اسکن و ثبت» | دو کارت جدا (۲ اسکن / ۳ ثبت) | عنوان‌های شماره‌دار «۲)» و «۳)» هیچ معنایی برای کاربر ندارند |
| زبانهٔ «هشدار» | فهرست انقضا | نامشخص اینکه با «موجودی» چه تفاوتی دارد |

---

## ۲) فهرست دقیق مشکلات

### الف) اضافه‌های فنی که باید از چشم کاربر حذف شوند
1. کلید API، نام کاربری/رمز سرویس، آدرس سرویس، آدرس استعلام → **حذف از UI** (اگر لازم شد، فقط در «حالت پشتیبانی»).
2. آدرس پروکسی و چک‌باکس مسیر جایگزین → حذف؛ خودکار و بی‌صدا انجام شود.
3. «کاوش‌گر اندپوینت» → حذف کامل (ابزار ما بود، نه محصول).
4. «دریافت کاتالوگ» و «تست منابع» → حذف از UI عمومی.
5. «ذخیرهٔ پاسخ خام» و «کپی گزارش» → حذف؛ به‌جایش گزارش خطای خودکار در پس‌زمینه.
6. «حذف رکوردهای بی‌نام» → حذف؛ نباید چنین رکوردی ساخته شود (قاعدهٔ I1).

### ب) حذف/ادغام صفحات
7. پنج زبانه زیاد است. «هشدار» زیرمجموعهٔ «موجودی» است → **ادغام**.
8. «دیتابیس» و «تنظیمات» دو چیز متفاوت‌اند و قاطی شده‌اند → جدا شدن.
9. «تاریخچه» باید روی هر قلم دارو هم دیده شود، نه فقط یک فهرست کلی.

### ج) مشکلات تجربه
10. عنوان‌های «۱)»، «۲)»، «۳)» → القای مرحله‌ای بودن در کاری که چرخه‌ای است.
11. بعد از ثبت، فرم پاک می‌شود ولی بازخورد کافی نیست (چه ثبت شد؟ موجودی قبلی/جدید چقدر شد؟).
12. حالت خالی (اولین اجرا) هیچ راهنمای واقعی ندارد.
13. خطای «بررسی آنلاین نتیجه نداد» طولانی و فنی است؛ باید یک جمله + یک عمل باشد.
14. روی موبایل، کارت «ثبت» خیلی بلند است؛ همهٔ فیلدها همیشه باز.

## ۳) ساختار پیشنهادی (۴ صفحه، بدون تنظیمات جلوی چشم)

```
┌───────────────┐
│  ۱. اسکن      │  ← صفحهٔ خانه (خانه همین است، نه داشبورد)
│  دوربین تمام‌صفحه + یک نوار پایین
└──────┬────────┘
       │ (پس از اسکن)
┌──────▼────────┐
│  ۲. ثبت       │  ← شیت از پایین، نه صفحهٔ جدید
│  نام/بچ/انقضا  │  فیلدهای کم‌مصرف جمع‌شده
│  + تعداد       │  عدد بزرگ، دکمهٔ بزرگ
└──────┬────────┘
       │
┌──────▼────────┐   ┌──────────────┐
│  ۳. موجودی     │   │  ۴. تنظیمات   │
│  جست‌وجو + لیست │   │  پشتیبان، لایسنس│
│  انقضا داخلش   │   │  درباره، پشتیبانی│
└───────────────┘   └──────────────┘
```

### صفحهٔ ۱ — اسکن (۹۰٪ زمان کاربر اینجاست)
- دوربین تمام‌صفحه، کادر راهنما، بدون منو و تب.
- نوار پایین: «جست‌وجو با نام» · «دستی» · «موجودی» · «تنظیمات».
- بالای صفحه: نام شمارنده + «آخرین پشتیبان: امروز».
- بازخورد لرزش + صدای کوتاه + یک نوار سبز «ثبت شد: ۳ بسته».

### صفحهٔ ۲ — ثبت (شیت)
- بالای شیت: نام دارو + شرکت (خوانا، بزرگ) و نشان اصالت در صورت وجود.
- سه عدد مهم: بچ، انقضا، تعداد. بقیه زیر «جزئیات» جمع می‌شود.
- سگمنت روش شمارش (تکی / کارتن / باز) — همان، ولی چیدمان واضح‌تر.
- دکمهٔ بزرگ «ثبت و اسکن بعدی» (پیش‌فرض) + «فقط ثبت».

### صفحهٔ ۳ — موجودی
- جست‌وجوی فوری بالای صفحه.
- فهرست کارتی: نام، موجودی (بسته + واحد)، نزدیک‌ترین انقضا، رنگ وضعیت.
- فیلتر: «همه / نزدیک انقضا / منقضی / کم‌موجود» — این همان «هشدار» است، ادغام‌شده.
- با لمس هر قلم: جزئیات + تاریخچهٔ همان قلم + اصلاح.

### صفحهٔ ۴ — تنظیمات
- پشتیبان‌گیری / بازیابی / «آخرین پشتیبان».
- لایسنس (وضعیت، تاریخ، دستگاه).
- درباره، راهنما، پشتیبانی.
- **حالت پشتیبانی** (پنهان، با ۷ لمس روی نسخه): همان ابزارهای عیب‌یابی امروز.

## ۴) اصول طراحی (برای فاز ۴)

1. **یک عمل اصلی در هر صفحه.** اگر دو دکمهٔ هم‌وزن داری، طراحی اشتباه است.
2. **اعداد بزرگ، متن کوچک.** کاربر با دستکش/عجله عدد می‌زند.
3. **بدون پاپ‌آپ.** بازخورد در همان محل (نوار پایین شیت).
4. **همیشه یک راه برگشت.** ثبت اشتباه با «واگرد» ۵ ثانیه‌ای.
5. **حالت‌ها از پیش طراحی می‌شوند:** خالی، آفلاین، خطا، بارگذاری، «یافت نشد».
6. **فارسی و RTL از روز اول**، اعداد فارسی در نمایش و لاتین در ورودی.
7. **تایپوگرافی ثابت:** یک فونت (وزیرمتن/ایران‌سنس) در سه وزن؛ اندازه‌ها روی مقیاس ۴px.
8. **رنگ با معنا:** سبز = سالم، کهربایی = نزدیک انقضا، قرمز = منقضی/خطا، آبی = عمل اصلی.

---

## ۵) چه چیزی از تجربهٔ امروز نگه می‌داریم

- سرعت و ایمنی منطق ثبت (سه روش شمارش).
- «بررسی آنلاین» نامرئی — ولی حالا کاملاً پشت صحنه، بدون هیچ فیلدی در UI.
- خروجی اکسل با دو شیت.
- پشتیبان JSON.

---

## ۶) لیست تأیید

1. چهار صفحه (اسکن، ثبت، موجودی، تنظیمات) قبول است؟
2. حذف کامل فیلدهای فنی از UI قبول است؟ (منتقل به «حالت پشتیبانی»)
3. ادغام «هشدار» در «موجودی» قبول است؟
4. صفحهٔ خانه = دوربین قبول است؟ (به‌جای داشبورد)
